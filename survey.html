Video VLM Token Compression Survey

在 VideoChat3 vision encoder 中加入 LACT，再只选择部分甚至最后一个 chunk 的视觉 token 给 LLM： 哪些任务可能受益，哪些性能从信息结构上就很难挽回？

执行结论

只保留最后一个 chunk，不是通用 video token compression，而是在假设最后状态是所有未知下游问题的充分统计量。 对 query-blind encoder 来说，这个假设通常不成立。它可能适用于低熵、全局、任务定义固定的输出；对需要时间边界、逐帧空间证据、稀有细节或多个事件—时间绑定的任务，性能往往无法靠更强 LLM 挽回。
可能有效

全局、冗余、低熵任务

视频类别、主导动作、场景/主题、粗摘要、事件是否出现、固定 schema 的在线状态检测。目标可由少量累计统计量表达。

条件有效

通用 VideoQA 与长视频检索

需要多 slots、时间锚点、多尺度细节或 query-conditioned selection。仅靠最后 chunk 的 query-blind state 风险很高。

高概率不可恢复

Grounding、tracking 与密集输出

精确时间边界、dense caption、逐帧 pointing/tracking、短暂 OCR、身份重现、任意多事件计数都要求保留可寻址证据。

最推荐方向：保留 temporal anchors，优先压缩 spatial tokens。以当前每 chunk 约 64 个 merger token 为例， R4 × 64 tokens 与 R1 × 16 tokens 的平均 LLM token budget 相同；后者保留 4 倍时间分辨率，更符合 temporal grounding 的需求。

我们实际在做什么

当前 LACT 不是在看到问题后选择证据，而是在视觉编码阶段对视频做 query-blind recurrent summarization； LLM 随后只接收选中的 encoder 输出。LACT 提供“历史可以影响未来 token”的路径，但没有保证历史内容可分离、可寻址或与绝对时间绑定。

4-frame local chunkchunk 内 full attention；局部 4-slot temporal embedding；2D RoPE。
→
Layer-wise LACT stateapply old state，再写入当前 chunk；顺序信息隐式存在，但没有显式 absolute-time address。
→
Post-encoder selectionR4 select-last 或 video-last 删除多数 chunk outputs；对应 timestamps 也被压缩。
→
Question + LLM问题此时才参与推理；被压掉的证据无法重新请求。

LACT 能提供的东西

  • 跨 chunk 的有序递归状态；
  • 适合累计 presence、粗计数、趋势或状态变化；
  • 未来 chunk token 可以包含过去语义；
  • 固定任务经专门训练后，可学到近似 sufficient statistic。

LACT 不自动提供的东西

  • 过去每个事件的独立 memory slot；
  • 事件与绝对 timestamp 的绑定；
  • 对训练时未知问题的细节保真保证；
  • 被删除 token 的空间坐标、文字像素和帧级身份轨迹。

压缩成功方案的共同模式

Pattern A

保留时间覆盖，压缩空间密度

Molmo 2、LLaVA SlowFast、InternVL router、PVC 都倾向让更多时间点至少留下少量 token，而不是让大段时间完全不可见。

Pattern B

问题先于选择

LongVU、PruneVid、GroundVTS 使用 query 或 LLM attention 决定保留什么。当前 LACT 在问题进入 LLM 前已经压缩，因此无法利用这项优势。

Pattern C

一个时间段对应多个 latent slots

MiniCPM 3D Resampler、VTG-LLM slots、HiCo hierarchy 都输出一组 token。单一 final chunk 的 spatial grid 并不是显式的历史 slot bank。

Pattern D

显式时间身份不随压缩消失

Qwen3-VL 的 T/H/W position 与 timestamp alignment、Molmo 2 的 per-frame timestamp、VTG-LLM absolute-time token 都保留“何时”。

Pattern E

多尺度旁路保护稀有细节

SlowFast、LongVU 双 encoder 等方案让高时间覆盖与高空间细节走不同路径，避免一个统一压缩率同时伤害两类信息。

Pattern F

压缩策略本身经过监督

InternVL ViCO、VideoChat-Flash short-to-long、GroundVTS progressive optimization 都训练压缩器。零 gate + 短 SFT 很难学成通用历史编码器。

为什么“VideoQA 平均分不掉”不能证明 grounding 安全

TTF 报告在 Qwen3-VL 上删除约 67% token 仍保留 99.5% baseline accuracy，ForestPrune 报告 LLaVA-OneVision 删除 90% token 后保留 95.8% 平均准确率； 这说明大量视频确实冗余，但这些平均值主要来自通用 QA/MCQ。专门面向 VTG 的研究则指出，朴素复用通用 pruning objective 会在边界敏感任务上显著退化。 因而“平均 QA 容忍高压缩”与“可以精确恢复时间边界”是两件不同的事。 TTF · ForestPrune · Keeping the Evidence Chain

哪些性能一旦压掉就无法由 LLM 挽回

1. Query-blind sufficient-statistic 不可能覆盖任意问题

假设视频包含姓名、车牌、动作次数、多个物体属性和几十个事件。压缩发生时问题未知，固定 final state 必须同时保留所有可能被问到的细节。随着视频长度增长，这是不可持续的。

2. 顺序记忆不等于绝对时间记忆

递归 state 可以区分“先后”，但没有 timestamp-conditioned K/V 时，无法稳定恢复“发生在第几秒”。只给最终 token 一个 timestamp 会把历史内容错误归到最终时间。

3. 单次 readout 暴露不了完整 state

最后 chunk token 是由当前 chunk query 读取 fast state 的结果。即使 state 内仍有信息，没有针对下游问题的 query，也未必能把所需历史维度读出来给 LLM。

4. Dense 输出要求 representation 随时长扩展

一段视频若有 N 个独立事件，dense caption、tracking、timeline 的输出信息量通常随 N 增长。固定大小 final state 不随 N 扩展，最终必然发生碰撞或遗忘。

5. 空间坐标不能从纯语义 summary 重建

pointing、tracking、Ref-VOS 依赖原 patch/frame 对应关系。删除 token 后只剩语义向量，LLM 无法恢复被删除的像素位置和遮挡轨迹。

6. 高压缩 benchmark 结果常被任务分布掩盖

MCQ 常能借助语言先验、全局动作和冗余帧作答；这不会测试短暂 OCR、精确边界或任意 needle。必须按任务信息需求分层评估。

对 VideoChat3-LACT 的设计建议

推荐主线：R1 temporal coverage + spatial compression + time-aware LACT

每个 4-frame chunk → local VideoChat3 attention → LACT update(K, V, absolute_time, Δt) → spatial resampler: 64 → 8/16 visual tokens → 2–4 LACT memory readout tokens（可选） → [timestamp / interval] + visual tokens → LLM 保留：每个 chunk 的时间锚点、顺序、粗空间证据 压缩：同一时间点内部的空间冗余 扩展：输出 token 数随视频时长线性但低斜率增长

为什么优于 R4 select-last：在近似相同 LLM token budget 下，它不把 3/4 时间点变成“只有隐式 state、没有显式地址”的信息。

优先级改动预期收益代价 / 风险
P0 保留所有 chunk timestamps；视觉 token 改为每 chunk spatial 64→16。 同等平均 token budget 下恢复 4× temporal anchors；最直接保护 grounding。 需训练 spatial resampler；每 chunk 均有少量 LLM token。
P0 把 absolute timestamp、normalized time 和 Δt embedding 注入 LACT update K/V 与 read query。 让 state 能绑定内容与时间，而不是只隐式记录次序。 改变 FW 模型；需从初始化重新训练。
P1 每个 macro group 输出多个 memory slots，并附 [t_start,t_end]；不要只复用最后 chunk grid。 不同事件可分离，readout 不再完全由最终帧内容决定。 slot 数与任务覆盖需调参。
P1 SlowFast 双路：所有 chunk 保留 1–4 个 motion/global tokens；稀疏关键 chunk 保留较多 spatial tokens。 兼顾时间覆盖和细节；已有 SlowFast/LongVU 先例。 需要关键帧策略，最好用变化度而非固定最后帧。
P2 问题可提前获得时，做 query-conditioned LACT readout 或二阶段检索。 显著改善 needle、任意属性 QA 和 VTG。 同一视频换问题时需重做轻量 readout；缓存接口更复杂。
限定用途 video-last 仅用于固定 ontology 分类、在线告警、全局摘要等低熵任务。 极致 LLM token reduction。 不要将其作为通用 VideoQA / grounding 表征。

评估必须覆盖四类互补任务

Global

通用理解

Video-MME、MVBench；判断全局 QA 是否能在压缩下保持。

Temporal

精确时间

TimeLens-Bench、Charades、ActivityNet、QVHighlights；报告 R1@0.3/0.5/0.7 与 mIoU。

Retrieval

稀有证据

单 needle 与 multi-hop NIAH；控制 needle 时间位置、持续长度和问题是否提前可见。

Dense

密集与细节

dense caption、短暂 OCR、计数；检查压缩是否只保留视频主旨。

Ablation

状态贡献

continuous / reset / gate-zero，比较 native 输出；不要以 teacher-forced NLL 替代正式指标。

Efficiency

真实成本

vision FLOPs、LLM prefill、peak memory、端到端 latency；区分 encoder 和 LLM 节省。

决策规则：若 B 在相同 token budget 下稳定胜过 A，说明主要瓶颈是 temporal anchor 丢失，应停止继续扩大固定 temporal select factor。若 D 仍无法接近 B，则单纯增加 LACT slots 不足，需要 query-aware retrieval 或保留更细时间网格。
